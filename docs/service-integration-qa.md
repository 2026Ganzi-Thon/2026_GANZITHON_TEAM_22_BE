## 사용자가 겪는 두 가지 변화

**공부를 끝내고 알림을 예약할 때** 사용자별 활성 예약을 찾아 해당 행만 변경합니다. 동시에 같은 입력을 보내도 예약은 한 건입니다. DB 잠금을 잠시 얻지 못하면 재시도하고, 이미 MySQL의 잠금 대기 시간 초과를 겪었으면 즉시 `503 REMINDER_TEMPORARILY_UNAVAILABLE`과 `retryable=true`를 반환합니다. 앱은 같은 경로와 본문으로 다시 요청하고, 응답의 상태가 `ACTIVE`일 때 단말 알림을 예약합니다.

**AI가 답하는 중 연결이나 DB에 문제가 생겼을 때** 모델이 답한 뒤에는 소유자·공부방 확인과 저장·정산 중 일시적인 DB 작업만 최초 포함 최대 3회 시도합니다. 한 요청의 재시도가 다른 사용자의 완료를 막지 않게 했습니다. 이미 커밋된 응답은 다시 읽어 반환합니다. 재시도 사이 방이 끝나면 새 성공 답변을 만들지 않고 기존 커밋이 확인되면 그 응답을 보존합니다. 확인된 사용량은 6.2의 캐시 읽기·쓰기를 포함해 한 번만 정산합니다. 비과금으로 확인된 제공자 오류는 답변 저장까지 실패해도 0원으로 처리합니다.

모델에 보내기 전 **예산 예약의 커밋 여부**를 확인할 수 없으면 해당 서버 시도에만 할당한 예약 ID로 0원 정산을 시도하고 `503 CHAT_ADMISSION_UNAVAILABLE`을 반환합니다. 앱은 원래 본문과 `clientRequestId`로 다시 확인합니다. 처음 예약이 롤백됐으면 다시 접수할 수 있고, 발송 전에 0원으로 정리한 기록만 남으면 `200 FAILED / CHAT_RESULT_UNAVAILABLE`이 최종 결과입니다. 다른 인스턴스가 접수한 예약은 이 정리의 대상에서 제외합니다. ## 팀원이 재현할 때

1. Windows에 Java 21 JDK, Node.js, MySQL 8 서버·클라이언트를 준비합니다. `JAVA_HOME`을 설정하고, MySQL이 기본 경로와 다르면 `GANZI_MYSQL_HOME`에 설치 폴더를 지정합니다.
2. 저장소 루트에서 `node scripts/verify-local.mjs`를 실행합니다. 실행기가 전용 DB와 자격증명을 만들고 모델 실호출을 끈 채 테스트·JAR 빌드·HTTP·재시작 검증을 수행합니다. 캐시된 Gradle 의존성으로 실행하려면 `GANZI_GRADLE_OFFLINE=true`를 설정합니다.
3. `build/verification-local/run-*/result.json`에서 테스트 수, HTTP, Flyway, 스키마, MySQL 종료 결과를 확인합니다. 같은 실행 폴더의 `source/build/libs/`에 시험한 JAR가 있습니다.
4. 표의 16명 경합과 실제 잠금 시간 초과는 같은 JAR로 별도 수행한 검증입니다. 재현할 때는 일회용 MySQL에서만 잠금 대기를 짧게 설정하고, 독립 연결에서 해당 시험 사용자의 행 잠금을 보유한 채 예약해 503을 확인합니다. 연결의 트랜잭션을 롤백한 후 같은 시각으로 두 번 예약해 반환 ID와 DB 건수를 대조합니다. [이번 실행의 실제 집계](verification/service-reliability-2026-11-18.json)
